# Forecasting decision and locked experiment

Protocol fixed before the first run on 26 October 2026. Script: `uv run python scripts/forecast_benchmark.py`. No model weights or extra dependencies are downloaded.

Use the retained 4,392 native hourly German SMARD observations, 1 April–1 October 2019 (exclusive end). Divide EUR/MWh by 1,000; repeat each observed hour across four scheduling slots without inventing extra observations. Whole UTC days: first 60% train, next 20% select ridge penalty from 0.1, 1, 10, 100, last 20% untouched test. Refit the selected penalty on train plus validation. Features: prices at the same UTC hour one/two/seven days ago, previous-day mean/min/max, preceding-week mean, cyclic hour and weekday. All lags precede that day's 00:00 UTC issue time; fit scaling only on the fitting block. Compare yesterday-repeat, last-week-repeat and ridge autoregression. This is an exploratory historical test, not evidence for today's market regime.

H1: ridge lowers held-out hourly MAE against both seasonal baselines. H2: at equal energy served it lowers realized charging cost against yesterday-repeat. Replay the unchanged synthetic four-van fixture on every test day with actual physical limits and perfect-known rosters, first energy-only, then the illustrative EUR15.20/kW/month component and zero prior peak for each independent day. Schedule against forecasts, bill against actual held-out prices. Perfect-price optimization is an oracle reference, not a forecast. Include all days and solver outcomes; any incomplete/non-optimal run prevents a minimum-regret claim. Report mean paired cost differences and exploratory 95% contiguous seven-day block-bootstrap intervals (1,000 replicates, seed 20261026); these are uncorrected for multiple comparisons. No future readiness, capex or operational savings claim is implied.

These are deliberately **unpublished-price-gap scenarios**. German next-day auction prices are ordinarily published before delivery, so use known prices rather than replacing them with predictions. The backtest does not show an advantage over already published prices. Building load, PV and uncertain duty cycles may create stronger forecasting needs, but this repository lacks linked depot measurements to evaluate those claims.

Candidate foundation models: Google's [TimesFM](https://github.com/google-research/timesfm) supports pretrained forecasting; 2.5 weights remain Apache-2.0, while the current 3.0 weights have a non-commercial/non-production licence. NVIDIA's [Time Series Prediction Platform](https://catalog.ngc.nvidia.com/orgs/nvidia/-/resources/nvidia_tspp_notebooks) is a training/evaluation/deployment framework rather than a plug-in pretrained price predictor. Nemotron's role here remains typed operations tools. Neither an LLM explanation nor GPU hosting establishes numerical forecasting skill. A future cloud TimesFM/TSPP comparison must use the same held-out dates and realized-cost evaluation. Neither has been run in this experiment.

Sources: [SMARD market downloads](https://www.smard.de/en/downloadcenter/download-market-data/), [SMARD wholesale-price description](https://www.smard.de/home/marktdaten/), and the source URLs/hashes in the retained dataset manifest. Credit: Bundesnetzagentur | SMARD.de, CC BY 4.0. Wholesale observations exclude the depot's actual retail contract, fees and taxes.

Machine-readable results are written to `docs/forecast-results.json`, with input and protocol SHA-256 and dates. Do not tune against its test block after reading the results.
