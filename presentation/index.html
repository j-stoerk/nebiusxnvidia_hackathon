The physical limits come first.

Each charger has its own rating and connector. Vans keep their assigned plug until departure. The planner respects battery limits, charging efficiency, taper, outages and the shared site connection.

FCFS, earliest-deadline-first and least-laxity-first use the same constraints. OR-Tools builds the optimized plan; an independent validator checks the allocations.

How much shared power is enough?

The afternoon pair needs 48 battery kWh in six hours. With 90% efficiency, that needs 53.33 grid kWh. Below 8.89 kW, there simply isn't enough energy.

The recorded workflow uses a real NVIDIA Nemotron model through Nebius Token Factory. It reads computed schedule facts, then applies an explicitly authorized simulated outage through a typed tool.

The solver replans and the validator checks again: every departure met at a 10 kW peak. Model explanations are not themselves mathematical certificates.

Run the editable application.

This hosted page contains the explanation and recorded demonstration. The complete planner runs locally from the downloadable build, with the React dashboard, FastAPI, Pandas and OR-Tools.

  1. Download and extract the test build.
  2. Install Python 3.11+ and uv, then run this command inside the extracted folder:
uv run --locked python scripts/run_demo.py

Open http://127.0.0.1:8000. Start the guided demo, edit the inputs, optimize, check capacity and simulate an outage. Node.js is unnecessary for this prebuilt package.

No API key or payment is required for planning. With no provider configured, the assistant clearly labels its output as a local computed summary. Live NVIDIA inference is optional, server-side and separately enabled with a persistent local allowance; the downloadable build never contains the team's key.
