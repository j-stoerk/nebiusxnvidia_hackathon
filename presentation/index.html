The physical limits come first.

Each charger has its own rating and connector. Vans keep their assigned plug until departure. The planner respects battery limits, charging efficiency, taper, outages and the shared site connection.

FCFS, earliest-deadline-first and least-laxity-first use the same constraints. OR-Tools builds the optimized plan; an independent validator checks the allocations.

Same energy targets. A lower peak.

In the four-van example, every van receives its requested energy: 84 battery kWh in total. The three greedy policies peak at 22 kW; the optimized schedule peaks at 8.89 kW.

How much shared power is enough?

The afternoon pair needs 48 battery kWh in six hours. With 90% efficiency, that needs 53.33 grid kWh. Below 8.89 kW, there simply isn't enough energy.

Explore the six-hour energy requirement here, then use the app to include charger occupancy, battery taper and the complete roster.

Questions become useful actions.

NVIDIA Nemotron on Nebius Token Factory reads computed schedule facts and can request an outage replan through typed tools. The optimizer creates the allocations, and independent checks return the updated result to the dashboard.

In the CH-01 outage example, every departure remains met at a 10 kW peak. The animation follows this same tool loop.

Run the editable application.

This hosted page explains the architecture and workflows. The complete planner runs locally from the downloadable build, with the React dashboard, FastAPI, Pandas and OR-Tools.

  1. Download and extract the test build.
  2. Install Python 3.11+ and uv, then run this command inside the extracted folder:
uv run --locked python scripts/run_demo.py

Open http://127.0.0.1:8000. Start the guided demo, edit the inputs, optimize, check capacity and simulate an outage. Node.js is unnecessary for this prebuilt package.

Planning runs without an API key. The assistant can summarize the current results locally or connect to Nemotron through the private backend.
